# PythonScan 一步导入漏洞库设计

日期：2026-10-14。开发分支：`develop`。

## 目标与操作流程

用户从外网下载 OSV 的 PyPI `all.zip`，将文件带入内网，在 GUI 点击“导入/更新漏洞库”并选择文件。程序在本机完成转换、校验和持久化；成功后立即使用新库，重启后继续使用。用户不需要 Python、外网转换脚本或增量基准管理。

同一入口兼容已有 PythonScan 全量 ZIP。现有 CLI `db import` 同步支持原始 OSV ZIP 和 PythonScan 全量 ZIP。现有 CLI `db update` 保留增量能力，但 GUI 本次不新增增量操作：选择增量 ZIP 时明确提示使用 CLI 更新或选择全量文件。

内网导入和扫描全程不发起网络请求。下载、自动联网更新、自动定时检查、拖拽导入、系统文件关联及新增发布到 GitHub Releases 不在本次范围。

## 导入目标与持久化

目标路径在程序启动时确定，优先级与现有接口一致：显式 `--db` 路径，其次 `PYTHONSCAN_DB`，否则用户目录 `.pythonscan/vulndb.zip`。

选择的 ZIP 是输入文件，导入只读取它，不覆盖、不移动它。转换结果和导入后的全量库写入目标路径；GUI、CLI 默认使用同一位置。GUI 原“选择漏洞库”改为持久化导入入口，不再只临时打开所选文件。显式自定义路径在相同启动参数或环境变量下继续使用，不新增用户配置文件。

首个导入成功时不生成旧库备份；目标已有可加载的全量库时，成功替换前保存一份 `vulndb.zip.bak`，只保留最近一次被替换的库。损坏的现有目标不能覆盖已有良好备份；应允许有效新库替换损坏目标以恢复使用，并提示旧目标未作为有效备份保存。

若输入文件与目标路径相同，按全量库校验并重新加载处理，不覆盖目标、不更新备份；同路径文件本身损坏时返回错误。

## 识别与转换

存在 `manifest.json` 时，按 PythonScan 库识别：`kind=full` 走全量校验与导入，`kind=delta` 提示该操作不支持增量。不能把包含无效 manifest 的 ZIP 回退为 OSV 原始库。

没有 manifest 时，读取 ZIP 内 JSON 公告，按 OSV 格式处理：

- 公告必须是对象，包含可用的 `id` 和可解析的 `modified`。非 JSON 文件忽略；无法解码或解析的 JSON、错误的核心字段结构报错，包含问题文件名，不静默跳过。
- 仅采集 `affected.package.ecosystem=PyPI` 的条目；撤回记录不纳入扫描数据。没有可用 PyPI 记录的文件拒绝导入，避免意外用空库覆盖当前库。
- 包名规范化，按同包 ID/别名合并；保持现有字段契约及同包多来源去重。
- 保留影响版本列表与范围，合并时根据条目内容去重，不能用范围展示文字去掉版本列表或无上界条目。匹配按“版本列表或范围命中”执行。这两项是直接导入正确数据所需的最小修正。
- 不抓取 PyPI 最新包版本，原始 OSV 导入的 latest 表为空。已有 PythonScan 全量库的 latest 表原样保留。

原始库的数据快照取有效 PyPI 公告中最近的 `modified` 的 UTC 日期，不用导入当天日期掩盖旧数据。另在 manifest 中记录 `imported_at`、原始文件 SHA256 和输入类型。该日期表示记录最新修改日，不承诺上游公告覆盖完整。

OSV 转换代码移入扫描器包内的共享模块，供内网导入和外网同步器使用。EXE 和安装包不依赖发行包之外的 `sync` 目录，继续只使用标准库。既有同步器参数及全量/增量产物协议保持兼容。

## 安装与错误恢复

导入分为准备和安装两个阶段：

1. 准备阶段在后台读取、转换并写出临时全量库。完整检查 schema、kind、manifest 声明哈希、包索引与对应数据文件、JSON 核心结构和计数一致性。原库继续保留。
2. 准备结果通过校验后，GUI 在主线程关闭当前数据库句柄，安装服务将备份及新库通过同文件系统临时文件和原子替换落盘，再重新加载目标库。

转换、校验或备份准备失败不替换原库。新库替换失败时原目标保持不变，GUI 重新加载原目标恢复使用；备份可能已刷新为这份仍在使用的原库，不能将该次操作显示为成功。失败清理本次临时文件，不删除输入 ZIP。

旧目标损坏或缺失时，失败不能声称恢复了可用库，应保持未加载状态并显示实际错误。导入产生的新库在安装前已确认可加载；安装后若因文件访问等异常无法重载，使用本次保存的旧库恢复目标及 GUI；没有旧有效库时明确提示未就绪，并允许重试导入。

本次只保证单个应用实例内扫描与更新互斥。其他进程占用目标文件导致替换失败时，提示关闭占用程序后重试，不尝试终止其他进程。外部直接修改库文件的并发冲突不引入跨进程锁服务。

## GUI 行为

- 按钮显示“导入/更新漏洞库”，选中 ZIP 后立即开始，无需额外命令或路径设置。
- 导入中显示“正在校验/导入漏洞库”，禁止扫描、再次导入和结果导出，输入框内容保留；转换不冻结主事件循环。
- 扫描进行中禁止导入。工作线程不读取 Tk 变量，在主线程捕获选项和数据库引用后传入。
- 成功后显示数据快照和记录数，清除旧扫描结果并关闭旧结果导出，保留依赖输入，允许立即重扫。
- 失败显示原因；原库可恢复时继续使用原库并保留原扫描结果，输入始终保留。
- 关闭 GUI 时清理本实例数据库句柄，后台结果不能继续更新已销毁的窗口；待处理临时导入结果需清理。
- 所有新增界面文案提供中文和英文。

## 验证与交付

采用现有 unittest，并补充以下有实际行为覆盖的测试：

- OSV ZIP 转换后的扫描能够检出仅有版本枚举的记录、带 GIT 范围的显式版本、合并多来源条目；撤回记录排除。
- 新格式识别、错误 ZIP/JSON/schema/hash/index 被拒绝，原库和输入保持不变；全量库兼容、增量误选有明确错误。
- 同一目标连续导入两批库，结果随数据变化且新实例加载的是新库；上一份有效库备份可恢复。
- 安装失败保留原库、恢复失败有真实错误，已有损坏库可被有效新库替换而不覆盖已有良好备份。
- GUI 导入成功后自动加载、保持输入、清理旧结果；失败恢复、扫描互斥和关闭窗口后的回调清理。
