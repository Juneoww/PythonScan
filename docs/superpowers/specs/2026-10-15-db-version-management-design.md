# 漏洞库下载归档与启用版本追踪

2026-10-15。用户已确认“外网下载管理＋内网启用追踪”，并明确要求继续实现。基线 develop `7798d48`，保留原始 ZIP 离线导入和全量兼容，扫描/导入不联网。

## 外网入口与归档

新增显式联网命令 `pythonscan db download --archive-dir <目录> [--lang zh|en]`。来源固定为官方 OSV PyPI HTTPS all.zip，不接受任意第三方 URL。归档默认是用户目录 `.pythonscan/downloads`；提供 Windows 启动脚本将本工作区的默认归档指向 `vulnerability-db`，便携包指向包旁 `vulnerability-db`。不引入调度和自动后台网络请求。

结构继续使用 `versions/<快照日期>_<内容指纹前12位>/osv-PyPI-all.zip、vulndb.zip、metadata.json`，以及根目录 `inventory.json`、`checks.jsonl`。版本 ID 的后缀使用实际转换库 index/data 的内容指纹，日期用于阅读而不是判定更新。已有手工归档的版本 ID 原样保留，匹配其文件哈希/内容指纹可复用。程序写入完整指纹，短前缀冲突不能覆盖旧目录。

下载过程仅一个进程写同一归档目录，使用独占锁文件，异常退出遗留锁给出明确移除锁后重试指引，不擅自删除其他进程锁。输入路径和已归档文件不被清理；版本相对路径必须限制在归档根目录，不能越界。

## 更新判定和失败边界

1. 若缓存来源 URL 与固定官方源一致，而且对应归档文件存在、哈希通过，GET 携带上次成功响应的 `If-None-Match`。返回 304 记录“未变化”，不读正文、不新建版本。不保存或使用未验证下载的 ETag。
2. 200 正文流式写入同文件系统的唯一临时目录；有 Content-Length 时校验长度，超时、网络错误、截断或格式错误都是失败。元数据来自这次 GET 响应，不把先前 HEAD 的属性配给新数据。
3. 原始 ZIP SHA256 相同则复用已有归档；ZIP 不同则对所有 JSON 文件按名称排序并规范化对象键、空白后计算内容指纹，忽略 ZIP 压缩和时间戳。此指纹比较 JSON 内容，并非任意数组排列的语义等价证明。
4. JSON 指纹相同表示仅打包变化；仍不新建版本。JSON 有变化时共享离线转换器生成、严格校验全量库；转换库 index/data 内容也相同则记为扫描数据未变化，不创建重复可用库版本。否则归档新版本。撤回、删除和修改均可能是有效更新，不能仅看计数或最大 modified。
5. 候选与元数据在临时目录准备完成后将目录原子提升，再原子更新 inventory。inventory 更新失败时尝试移回本次新目录，保留原清单；若恢复失败明确报错，旧版本仍不可覆盖。检查日志追加成功、未变、失败；错误不能显示为“暂无更新”。不能保证上游每次检查都有变化，只保证相同数据不冒充新版本。

inventory 增加成功来源缓存与最后一次成功检查；保留既有版本列表及历史字段。checks.jsonl 保留每次检查 UTC 时间、状态、原因和对应版本，失败不更新成功来源缓存。没有 ETag 时仍以哈希正确去重。缓存对应文件损坏/丢失时不发条件请求，重新下载修复；遇损坏的已有版本报出位置，不能将它当作有效复用版本。

## 启用版本与离线导入

新增共享离线身份模块，生成文件 SHA256、规范 JSON 指纹和版本 ID。扫描库内容指纹只覆盖 index/data，不含导入时间、来源等 manifest 字段。

准备导入时校验并计算实际内容指纹，向候选 manifest 写 `version_id`、`content_sha256` 及导入时间；不信任输入声明的身份而跳过计算。目标已有有效库且内容相同，视为重复导入，保留目标文件、备份及原启用信息。原始源、源内容指纹另行保存，不能混同于扫描库指纹。

安装沿用准备/安装/恢复服务，将候选 ZIP 的身份与数据一起原子替换。GUI 重载失败则连同启用身份恢复旧 ZIP；不写一个可能与实际文件脱节的 current.json。下载归档不自动启用；“最新归档”和“实际启用”明确区分。普通重复导入保持快照；增量即使内容相同也必须推进其 target 快照以维持后续 base 链。

已有无身份字段的全量库可加载，按实际 index/data 派生身份，不要求重新下载。增量更新也必须生成新的内容身份并经过同一安装/备份路径；不能保留旧库身份。直接复制、手工还原的库以实际加载的文件为准，记录不承诺全系统所有自定义启动路径统一。

GUI 显示快照、版本、指纹和实际路径，中英文齐备。`db info` 显示同样字段及已有记录数等信息。身份写入失败或数据库不可用时，不能显示新版本已启用。下载和导入日志不得互相混称。

## 验证与交付

用本地 HTTP 测试服务或可控传输替身验证首次 200、304、相同 ZIP、重新打包、同日真实变更、无 ETag、截断/网络失败、损坏归档、索引写入失败和锁冲突。测试文件/版本数量以及旧清单、缓存内容，不只断言请求调用次数。

身份测试覆盖旧全量兼容、导入两版、同内容重复导入备份不变、身份伪造重算、安装/GUI 重载失败恢复，以及增量后身份变化。保留全部现有测试，运行隐藏 Tk/mainloop 测试。外网实际运行下载两次，证明重复检查不增加库版本；不安装到用户默认路径。
