# PythonScan 新手操作手册

## 开发版 0.2.0.dev1：最简单的导入与替换方式

更新日期：2026-10-15。新功能需使用开发版 EXE 或当前源码，已发布的 v0.1.0 EXE 仍按下方旧版手册操作。

1. 在外网下载 [OSV PyPI 原始 all.zip](https://osv-vulnerabilities.storage.googleapis.com/PyPI/all.zip)，不解压，传入内网。
2. 打开开发版程序，点击 **导入/更新漏洞库**，选择 ZIP，等待完成后扫描。每次更新重复这两步。

程序会离线转换、完整校验并安装到固定管理路径，成功后自动加载，重启仍然有效。默认路径是 `%USERPROFILE%\.pythonscan\vulndb.zip`；指定启动 `--db` 时维护该路径，否则优先使用 `PYTHONSCAN_DB`。命令行等效操作为 `pythonscan.exe db import C:\Transfer\all.zip`。

已有 PythonScan 全量 ZIP 也可直接导入。成功替换会在目标文件旁生成 `.bak`，保存上一份有效库；原目标损坏时保留现有有效备份。导入失败会保留或恢复旧库。需要手动回滚时，关闭程序，将 `.bak` 复制覆盖目标 ZIP，再重新启动。导入同一个目标文件只做校验和重载，不更新备份。GUI 不接受增量包，增量维护请用 `db update`。

以下章节保留为 **v0.1.0 操作说明**，其中“选择漏洞库…”和外网预转换流程仅适用于旧版。

> 适用版本：v0.1.0（含桌面端）　|　更新日期：2026-09-14
>
> 本手册面向第一次接触本工具的同学，按"是什么 → 怎么装 → 怎么用 → 漏洞库怎么更新 → 出问题怎么办"的顺序编写。照着复制命令即可完成操作。

## 1. 这个工具是什么

输入 pip 依赖包的**名称和版本号**，检查它们有没有**已知安全漏洞**（CVE/GHSA/PYSEC），并给出**修复建议**（升级到哪个版本）和**报告**（JSON / HTML / PDF）。

它由三个部分组成，平时只需要关心前两个：

| 组成部分 | 在哪台机器上 | 作用 |
| --- | --- | --- |
| ① 扫描器（`pythonscan` 文件夹） | **内网机** | 命令行 + 图形界面，离线扫描，不用联网 |
| ② 漏洞库文件（一个 `.zip`） | **内网机** | 漏洞数据，摆渡进来，可单独更新 |
| ③ 同步器（`sync` 文件夹） | **外网机**（可联网） | 从 OSV.dev 抓取最新漏洞数据，生成漏洞库文件 |

核心设计：**程序和数据分离**。升级漏洞库 = 换一个数据文件，程序永远不用重装。

```
外网机（能上网）                          摆渡（U盘/网闸）           内网机（隔离）
┌─────────────────────────┐                                  ┌──────────────────────────┐
│ 同步器抓取漏洞数据          │ ──── 全量库.zip 或 增量包.zip ────→ │ db import / db update     │
│ 生成漏洞库文件             │                                  │ 之后正常 scan / 图形界面   │
└─────────────────────────┘                                  └──────────────────────────┘
```

## 3. 首次部署（10 分钟）

### 第 0 步（最省事的方式）：直接用打包好的 exe

如果拿到的是 `release\` 目录（仓库自带 Windows 免安装版，**不需要装 Python**）：

```bat
:: 桌面图形界面：双击 release\pythonscan-gui.exe 即可
:: 命令行：
release\pythonscan.exe db import release\pypi-advisories-20260920.zip
release\pythonscan.exe scan
```

首次先执行第一条命令导入预置漏洞库，之后所有命令把 `python -m pythonscan` 换成 `release\pythonscan.exe` 即可。以下章节仍以源码方式（`python -m pythonscan ...`）讲解，exe 用户自行替换命令前缀，其余步骤完全一致。

### 第 1 步：把两样东西拷进内网机

用 U 盘/网闸把整个项目文件夹拷到内网机任意目录（下文以 `D:\PythonScan` 为例），其中必须有：

- `pythonscan\` 文件夹（扫描器程序）
- 一个漏洞库压缩包，例如 `pypi-advisories-20260913.zip`（在外网机生成，见 [第 6 节](#6-漏洞库更新重点)；如果同事已经摆渡过，直接找他要）

### 第 2 步：导入漏洞库（只需做一次）

打开 cmd（按 `Win + R`，输入 `cmd`，回车），执行：

```bat
cd /d D:\PythonScan
python -m pythonscan db import pypi-advisories-20260913.zip
```

看到类似下面的输出就成功了：

```
全量库已导入: C:\Users\你的用户名\.pythonscan\vulndb.zip（快照 2026-09-13，19,821 条记录，13,392 个包）
```

> 导入后漏洞库放在用户目录 `.pythonscan\vulndb.zip`，以后**不用再指定路径**。

### 第 3 步：跑第一个扫描验证

```bat
python -m pythonscan scan
```

按提示逐行输入（一行一个），最后**敲一个空行**开始扫描：

```
> requests==2.28.0
> flask==2.3.2
>      ← 这里直接回车（空行）结束录入
```

看到漏洞列表和"汇总"行，部署完成 ✅

> **验证小技巧**：`requests==2.28.0` 是一个必然有漏洞的版本（至少含 CVE-2023-32681），用它测试一定能看到检出效果。

## 4. 日常使用一：桌面图形界面（推荐新手）

### 启动

```bat
cd /d D:\PythonScan
python -m pythonscan gui
```

> 想不显示黑色控制台窗口，用 `pythonw -m pythonscan gui`（注意是 pythonw）。
> 也可以 `pip install -e .` 安装一次，以后双击 Win+R 直接输 `pythonscan-gui` 启动。

### 界面操作顺序（从上到下）

1. **左上角"选择漏洞库…"**：如果状态栏已是绿色"漏洞库就绪：快照 xxxx"可跳过；否则点它选中漏洞库 zip 文件（可以是导入过的默认库，也可以直接选任何一份全量库 zip，无需提前 import）；
2. **中间大输入框**：一行填一个依赖，支持这些写法（效果相同）：

   ```
   requests==2.28.0     ← 标准写法
   flask 2.3.2          ← 空格分隔
   urllib3@1.26.5       ← @ 分隔
   django               ← 只写包名 = 列出该包全部已知漏洞（结果会标注"未固定版本"）
   # 这是注释，会被忽略
   ```

   也可以点 **"导入清单文件…"** 直接选一个 `requirements.txt` 或自己写的 `deps.txt` 填入；
3. **勾选项**："未固定版本的依赖从当前环境探测已装版本"——勾上后，只写包名的依赖会自动读取本机 Python 环境里实际安装的版本来精确扫描；
4. **点"开始扫描"**：结果区立刻显示彩色结果（红色=有漏洞、绿色=干净、橙色=修复建议）；
5. **导出报告**（扫描后三个按钮自动点亮）：
   - **导出 JSON**：结构化数据，给其他系统/脚本用；
   - **导出 HTML**：成型报告，浏览器打开，推荐存档用；
   - **导出 PDF**：自动调用本机 Edge/Chrome 把报告打印成 PDF；如果机器上没有浏览器，会提示改为手动打开 HTML 后 `Ctrl+P` 打印。

### 小提示

- 扫描过程中按钮会变灰，几秒内完成（1 万条漏洞库加载 + 50 项依赖扫描 ≤ 10 秒）；
- "清空"按钮会同时清空输入和结果；
- 更换漏洞库 zip 后**立即生效**，不用重启界面。

## 5. 日常使用二：命令行

### 5.1 三种输入方式（选一种即可）

```bat
:: 方式一：交互式录入（什么都不带，回车后逐行输入，空行结束）
python -m pythonscan scan

:: 方式二：依赖清单文件（格式与交互式一致，一行一个）
python -m pythonscan scan -i deps.txt

:: 方式三：直接扫现成的 requirements.txt
python -m pythonscan scan -r requirements.txt
```

> `-i` 和 `-r` 不要同时用。`deps.txt` 就是你自己新建的文本文件，内容如：
> ```
> requests==2.28.0
> flask==2.3.2
> pyyaml==5.3.1
> ```

### 5.2 输出报告文件（可自由组合）

```bat
:: 三种报告全要
python -m pythonscan scan -i deps.txt -o report.html --json report.json --pdf report.pdf

:: 只要 HTML
python -m pythonscan scan -r requirements.txt -o report.html
```

| 参数 | 产物 | 用途 |
| --- | --- | --- |
| `-o report.html` | 成型 HTML 报告 | 人看、存档、打印 |
| `--json report.json` | 结构化 JSON | 给脚本/平台二次处理 |
| `--pdf report.pdf` | PDF 报告 | 正式提交物（需本机有 Edge/Chrome） |

### 5.3 其他常用参数

```bat
python -m pythonscan scan --use-installed      :: 只写包名的依赖，自动探测本机已装版本
python -m pythonscan scan --fail-fast          :: 发现第一个漏洞就停止（快速筛查）
python -m pythonscan scan --lang en            :: 英文输出
python -m pythonscan scan --db D:\libs\my.zip  :: 临时指定别的漏洞库文件
python -m pythonscan scan --stale-days 30      :: 库超过 30 天就警告（默认 90）
```

### 5.4 退出码（写脚本时用）

| 退出码 | 含义 |
| --- | --- |
| `0` | 扫描完成，没有已知漏洞 |
| `1` | 扫描完成，**发现有漏洞** |
| `2` | 运行出错（库没导入/文件不存在/参数错误等） |

批处理示例（有漏洞时弹提示）：

```bat
python -m pythonscan scan -i deps.txt
if errorlevel 1 echo 发现漏洞，请查看报告！
```

### 5.5 漏洞库管理命令

```bat
python -m pythonscan db import 全量库.zip    :: 首次部署/重新部署
python -m pythonscan db update 增量包.zip    :: 日常更新（见第 6 节）
python -m pythonscan db info                 :: 查看当前库的快照日期、记录数
```

## 6. 漏洞库更新（重点）

### 6.1 先弄清楚：你属于哪种情况

| 情况 | 你要做的 |
| --- | --- |
| **A. 我是内网使用者**，同事负责在外网机生成漏洞库 | 只需 [6.4 应用更新](#64-第三步内网机应用更新) |
| **B. 我负责在外网机生成漏洞库** | 看 [6.2 → 6.3 → 6.4 全流程](#62-第一步外网机生成漏洞文件) |
| **C. 我的内网机其实能碰到一台能上网的电脑** | 同 B |

### 6.2 第一步：外网机生成漏洞文件

**准备什么：**

1. 一台**能上网的机器**（Windows/Linux 均可），装有 Python ≥ 3.9；
2. 整个项目文件夹（`pythonscan\` 和 `sync\` 两个文件夹必须在，同步器要复用程序里的库格式代码）；
3. 如果这台机器访问 Google 存储需要代理（公司常见）：准备好代理地址，如 `http://127.0.0.1:7890`；
4. 磁盘空间约 200MB（下载临时文件 + 生成结果）。

**怎么做：**

```bat
cd /d D:\PythonScan

:: 首次生成（全量库，约 30MB 下载 + 生成 15MB 库文件，几分钟）
python -m sync.sync build --out pypi-advisories.zip --proxy http://127.0.0.1:7890
```

- 如果外网机**不需要代理**，去掉 `--proxy` 参数即可；
- `--out` 是输出文件名，建议带上日期：`--out pypi-advisories-20261001.zip`；
- 可选参数 `--fetch-latest`：额外抓取每个包在 PyPI 上的最新版本号（首次约需十几分钟），写入后扫描报告能提示"最新版本是否干净"。不加也能正常用；
- 看到这样的输出即成功：

```
全量库已生成: pypi-advisories.zip
  快照 2026-10-01  19,9xx 条记录 / 13,xxx 个包
  文件大小: 15 MB（内网端: pythonscan db import pypi-advisories.zip）
```

### 6.3 第二步：生成增量包（日常更新，推荐）

**前提**：外网机上还留着**上一次**生成的全量库文件（比如上个月的 `pypi-advisories-20260913.zip`）。

```bat
python -m sync.sync build --prev pypi-advisories-20260913.zip --out delta-20260913-to-20261001.zip --proxy http://127.0.0.1:7890
```

- 程序会自动对比新旧数据，只把**有变化的部分**打进增量包——通常只有几 KB 到几 MB，摆渡非常快；
- 输出会显示 `变更 N 个包, 删除 N 个包`；
- **把上次的旧全量库归档保存好**，它是下次生成增量的基准。

**摆渡什么：**

| 场景 | 拷进 U 盘的文件 | 大小 |
| --- | --- | --- |
| 内网机第一次部署 / 版本断档了 | 新的全量库 `pypi-advisories-日期.zip` | 约 15MB |
| 内网机已装上个月的全量库 | 增量包 `delta-xxx.zip` | 几 KB ~ 几 MB |

### 6.4 第三步：内网机应用更新

先看一下当前库的快照（记下日期）：

```bat
python -m pythonscan db info
```

**情况一：拿到的是增量包**（内网机当前快照 = 增量包的基准日期时才能用）：

```bat
python -m pythonscan db update delta-20260913-to-20261001.zip
```

成功输出：

```
增量已应用: 快照 2026-09-13 -> 2026-10-01（19,9xx 条记录）
```

**情况二：拿到的是新全量库**（或上面报"版本不衔接"时）：

```bat
python -m pythonscan db import pypi-advisories-20261001.zip
```

> import 会直接覆盖旧库，覆盖前自动做完整性校验，放心操作。
> 图形界面用户：也可以不执行任何命令，直接点"选择漏洞库…"选新的 zip 文件。

**更新后验证**：`db info` 看快照日期是否变成新日期；随便扫一个包确认正常。

### 6.5 更新相关报错对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `增量包基于快照 X，当前库快照为 Y，版本不衔接` | 中间漏摆渡了某次增量 | 按日期顺序逐个补应用中间的增量包；或直接 `db import` 最新全量库（省事，推荐） |
| `文件校验失败: xxx（内容损坏或被篡改）` | 拷贝过程中文件损坏 | 重新拷贝一次该 zip |
| `漏洞库不存在: ...（请先执行 db import）` | 还没导入过库 | 先 `db import` 全量库 |
| 报告顶部黄色横幅"漏洞库快照已 N 天未更新" | 库超过 90 天没更新（阈值可用 `--stale-days` 调） | 按本章流程更新一次库 |

### 6.6 更新频率建议

- **常规**：每月一次增量（外网机跑一条命令 + 摆渡一个小文件）；
- **重要项目上线前**：临时更新一次全量库，确保覆盖最新披露的 CVE；
- 漏洞库快照日期会**强制显示在每份报告里**，审计时以该日期为准。

## 7. 依赖输入格式详解

一行一个依赖，以下写法**全部等价**：

```
requests==2.28.0
requests === 2.28.0
requests@2.28.0
requests 2.28.0
```

其他规则：

| 写法 | 工具如何处理 |
| --- | --- |
| `flask[async]==2.3.2` | 方括号附加选项自动忽略 |
| `numpy>=1.21 ; python_version >= "3.10"` | 版本范围/环境标记无法精确匹配 → 按**未固定版本**处理并列出该包全部漏洞 |
| `flask==1.0.*` | 通配符版本 → 按未固定版本处理 |
| `# 注释`、空行、`-r xxx.txt` 等 pip 选项行 | 自动忽略 |
| `只写包名`（如 `requests`） | 标注"未固定版本"，列出该包**全部历史漏洞**，并建议先 `pip show 包名` 查到版本后精确复扫；配合 `--use-installed` 可自动探测版本 |
| 无法解析的乱码行 | **跳过不中断**，在报告"告警"里列出 |

> **重要**：版本号请填 PyPI 上的准确发布版本（用 `pip show 包名` 或 `pip freeze` 查看），例如 `2.31.0` 而不是 `v2.31`。版本不准会导致漏判。

## 8. 扫描结果怎么读

以命令行输出为例（图形界面内容相同）：

```
[危险] requests 2.28.0 — 4 个已知漏洞                 ← 红色：这个包有漏洞
  · GHSA-j8r2-6x86-q33q [中危] (CVE-2023-32681, PYSEC-2023-74)
      Unintended leak of Proxy-Authorization header in requests
      影响范围: >=2.3.0, <2.31.0    修复版本: 2.31.0
      详情: https://osv.dev/vulnerability/GHSA-j8r2-6x86-q33q
修复建议: 升级到 2.33.0（覆盖 4 个漏洞）               ← 绿色：升到这个版本，本包漏洞全修
--------------------------------------------------------
汇总: 3 项依赖 | 受影响 2 | 未固定版本 1 | 高危 1 中危 4 低危 1 | 未评级 0
漏洞库快照: 2026-09-20                                ← 审计以此日期为准
```

| 字段 | 含义 |
| --- | --- |
| `GHSA-xxx / CVE-xxx / PYSEC-xxx` | 同一个漏洞在不同权威库的编号，括号里是别名 |
| `[严重/高危/中危/低危/未评级]` | 严重级别（来自 CVSS 评分分级） |
| `影响范围` | 受影响的版本区间，对照你用的版本 |
| `修复版本` | 官方修复该漏洞的首个版本 |
| `修复建议: 升级到 X` | 覆盖该包**全部**已知漏洞的最低升级版本；显示"需人工确认"时请点开详情链接自行核对 |
| `[警告] xxx (未固定版本)` | 你没给版本号，列出的是该包全部历史漏洞，不代表你用的版本受影响 |

HTML/PDF 报告额外包含：统计卡片、严重级别分布、干净依赖清单、告警附录，可直接作为整改依据存档。

## 9. 常见问题 FAQ

**Q1：启动就报 `漏洞库不存在`？**
还没导入漏洞库。执行 `python -m pythonscan db import 全量库.zip`，或在图形界面点"选择漏洞库…"。

**Q2：扫出来是空的/全安全，可信吗？**
结果只覆盖**漏洞库快照日期之前**已收录的公开漏洞。请先确认 `db info` 里的快照日期足够新；另外库只收录 PyPI 生态，非 PyPI 包查不到。

**Q3：PDF 导出失败？**
PDF 靠本机 Edge/Chrome 无头打印生成。确认机器上有 Edge 或 Chrome；实在没有就导出 HTML，用浏览器打开后 `Ctrl+P` 手动另存为 PDF。

**Q4：我想扫另一个 Python 项目的依赖？**
在那个项目目录执行 `pip freeze > requirements.txt`，然后 `python -m pythonscan scan -r 那个路径\requirements.txt`。

**Q5：内网机换人了/库文件删了怎么办？**
重新 `db import` 一次全量库即可，程序目录没有任何状态。

**Q6：一次最多能扫多少个包？**
没有硬限制。50 项依赖 10 秒内出结果；上千项也能跑，只是线性变慢。

**Q7：能把工具装成命令直接敲 `pythonscan` 吗？**
可以：`pip install -e .`，之后命令行用 `pythonscan scan ...`，图形界面用 `pythonscan-gui`。

**Q8：报告里"未评级"是什么意思？**
该漏洞来源（如部分 PYSEC 记录）没有提供 CVSS 评分，工具不猜测等级，如实标注"未评级"。

## 10. 命令速查表

```bat
:: ---------- 内网机：扫描 ----------
python -m pythonscan scan                          交互式录入扫描
python -m pythonscan scan -i deps.txt              扫描清单文件
python -m pythonscan scan -r requirements.txt      扫描 requirements
python -m pythonscan scan -i deps.txt -o r.html --json r.json --pdf r.pdf
python -m pythonscan scan --use-installed          环境探测未固定版本
python -m pythonscan gui                           桌面图形界面

:: ---------- 内网机：漏洞库 ----------
python -m pythonscan db import 全量库.zip           导入/重置漏洞库
python -m pythonscan db update 增量包.zip           应用增量更新
python -m pythonscan db info                       查看库快照信息

:: ---------- 外网机：生成漏洞库 ----------
python -m sync.sync build --out pypi-advisories.zip --proxy http://代理:端口
python -m sync.sync build --prev 上一版.zip --out delta.zip --proxy http://代理:端口
```

有任何命令拿不准，加 `-h` 看帮助：`python -m pythonscan -h`、`python -m pythonscan scan -h`、`python -m sync.sync build -h`。
